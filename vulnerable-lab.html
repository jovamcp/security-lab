Panel de vulnerabilidades

🛡️ Estado del lab

✕
CSP: unsafe-inline activo

No hay Content Security Policy restrictiva. Scripts inline y inyectados se ejecutan libremente.

✕
Sin Subresource Integrity

jQuery y Lodash se cargan sin atributo integrity. Un CDN comprometido ejecutaría código malicioso.

✕
Script por HTTP (no HTTPS)

jQuery se carga por HTTP plano, expuesto a ataques Man-in-the-Middle.

✕
XSS Reflejado

El input de búsqueda se inserta con innerHTML sin sanitizar.

✕
XSS Almacenado

Los comentarios se renderizan como HTML. Un atacante puede persistir scripts maliciosos.

!
SQL Injection (simulado)

Login acepta ' OR '1'='1 como bypass. Consulta sin parámetros preparados.

✅ Cómo practicar

  1. Inyecta <script>alert(1)</script> en la búsqueda
  2. Publica un comentario con HTML o script
  3. Usa ' OR '1'='1 en el login
  4. Inspecciona los scripts cargados (sin SRI)
  5. Revisa la respuesta en HTTP Observatory
